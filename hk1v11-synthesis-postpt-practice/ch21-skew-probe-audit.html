探针（isprx tcl）：`report_timing -delay_type ${delay_type} -group RX_CLK -through u_LOGIC_CENTER/BUFFER_I/INDATA_SYNC_reg* -max_paths 100 -nworst 20 -derate`（无 -from/-to）；perl 取每文件第一条 slack（get_phy L28、merge L45-62）。 - `-through INDATA_SYNC_reg*` 单过滤 → 同一报告混两类路径：**FF→FF**（INDATA_SYNC→INDATA_SYNC_D1）与 **port→FF**（dout_lane[*]→INDATA_SYNC_reg_*）。 - **max 行（2.050226 @wc_cworst）= FF→FF setup**：`INDATA_SYNC_reg_11_ → INDATA_SYNC_D1_reg_11_`，launch RX_CLK 边沿 0.000000 / capture 3.810000（`read_cons.log:419` create_clock RX_CLK 3.81ns ≈262.5MHz（精确 262.47）），arrival 4.472315、required 6.522541（CK 7.089138 − CRPR 0.013034 − uncertainty 0.400000 + setup 0.179631 计入），slack 2.050226。 - **min 行（0.081905 @wc_cworst）= port→FF hold**：`dout_lane[7] → INDATA_SYNC_reg_7_`，launch 边沿 3.810000 + `input external delay −0.300000`（`set_input_delay 0.3/−0.3 -clock RX_CLK`，read_cons L1005-1023）+ IOBUF 0.109526 → arrival 3.619526；capture 边沿 0.000000，CK 3.391954 + uncertainty 0.150000 − hold 0.004333 → required 3.537621；slack 0.081905。**±0.3ns input delay 模型 + 0.15ns uncertainty 把 3.81ns 窗口吃到只剩 ~0.08**。 - 所以「max/min 都贴 0、差距小」的真相：**两行是不同路径、不同窗口的各自最差 slack**——setup 借一个 3.81ns 周期、hold 被 ±0.3 模型压线；数值接近只是两个窗口都紧。这不是 bus skew 的最大/最小，也不跨行可比。 ### 3.2 两个负角是真违例，量级定性 - **wc_cbest_125 min = −0.051536**：port→FF hold，`dout_lane[5] → INDATA_SYNC_reg_5_`（arrival 3.621104 vs required 3.672640），同型负 slack 一族（−0.050469/−0.050202/−0.049138…）——**~50ps 级多 bit 真 hold 违例，cbest 角时钟最快所致，建议列入跟办**。 - **lt_typical_m40 min = −0.000113**：FF→FF hold（`INDATA_SYNC_reg_0_ → D1_reg_0_`，CRPR −0.129712 对冲不了 uncertainty 0.150000），0.1ps 量级 ≈ 数值噪声。 - 卫生问题：rpt 头回显 `-input_pins -sort_by slack` 而磁盘 tcl 没有（两项目同）——服务器执行版与仓库版漂移，不改 path 集合与数值，但回传同步时应统一。 ### 3.3 2M23 的 min=7.0~9.0 怎么来的（为什么不可比） - 探针不同：2M23 isprx 是 `-group RX0_OD_CLK_DIV2 -rise_through dout_lane_L0[*] -through .../I_INDATA_D1_reg*` **双过滤 → 只剩 port→FF 一类**（18 条，无 FF startpoint）。 - 时钟不同：捕获时钟是片内 DIV2 生成时钟（`create_clock RX0_OD_CLK 5.04` → `create_generated_clock RX0_OD_CLK_DIV2 -edges {2 4 6}`，周期 **10.08ns**，rise 沿在 2.52/12.60/…）；`set_input_delay 0`（无 ±0.3）；**DIV2 上无 uncertainty**（generated 不继承 master 的 ±0.4/0.15）。 - min=7.237304 的分解（`dout_lane_L0[8] → I_INDATA_D1_reg_8_`）： ``` 7.237304 ≈ 10.080000（launch 12.600000 − capture 2.520000，恰 1 个 DIV2 周期） − 3.354717（capture 网络 4.546443 − launch 网络 1.191726） + 0.360863（数据路径） + 0.146561（hold） + 0.004598（CRPR） ``` → 边沿差一项即达 slack 的 **1.39 倍**（10.08 / 7.237304；若以数据到达 14.152589 为分母则占 71%）。它是该约束模型下的真实 slack（不是排序假象），但 1V11 与 2M23 的 min 差 ~6.7ns 里：边沿基准 10.08 vs 3.81（+6.27）、input delay 0 vs −0.3、uncertainty 无 vs 0.15——**全是时钟架构/约束口径差，只有零头是电路差**。1V11 若套 input delay=0、无 uncertainty 模型，其 port→FF hold 同样是 6~7ns 量级。「max−min 差距大/小」不能跨项目当裕度比。 ### 3.4 io 行缺失机制（约束决定行存在性） - 1V11 io tcl（L12-17）：`-from [get_ports SCL_I]` + `-to [get_ports SDA_OE]`。`SCL_I` 只有 `create_clock I2C_CLK 500ns`（read_cons L433，无 input delay）→ 从端口出发只有 clock network，无 data path；`SDA_OE` 无任何约束（grep 零匹配）→ 无约束 endpoint。两段均 "No constrained paths."（各 36 行、736B）→ perl 提不出 slack → **csv 里根本没有 io 行**。 - 2M23：`I2C_CLK 500ns` + `set_input_delay 1/−1`（CSCL_I/CSDA_I，L813-819）+ `set_output_delay 1/−1`（I2C_SDA_OE，L987/989）→ io 行存在：io_max=**241.741440**（`I2C_BIT_CNT_reg_1_ → I2C_SDA_OE`，required 497.000000 = 500 − 2.0(uncertainty) − 1.0(output delay)，arrival 255.258560）；io_min=**251.998322**（required 1.150000 = 0.15 + 1.0，launch 沿 250 vs capture 0 的半周期错位，与 2.3 同源机制）。注意 2M23 io 报告第一个探针对象不存在（SEL-003/005），其 io 行实际只有输出侧。 - 顺带：1V11 的 io rpt 是 **10-22 旧代产物混在 10-28 latest 目录**（ls 时间戳 10:58 vs 11:19）——latest 目录混代，需清理重跑。 --- ## 4.
